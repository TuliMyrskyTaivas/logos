# AGENTS.md

Guidelines for AI coding agents working in the Gûldvegt service. This is a
separate Go module; read this file before making changes here. It supplements
the root-level `AGENTS.md` (the root Python rules do not apply to this module).

## Overview

Gûldvegt is an HTTP service that serves precious metals bullion and
investment coin quotes. It is built on the Echo v5 web framework and exposes
the endpoints defined in `api/openapi.yaml` (OpenAPI 3.2):

- `GET /quotes/bullions`
- `GET /quotes/coins`

Incoming requests are authenticated with an HMAC-signed JWT in the
`Authorization: Bearer <token>` header.

## Build

The build command is:

    go build -o guldvegt.exe cmd/api

Run it from the `gûldvegt/` directory. The entry point is the package path
`cmd/api` (do not use `./cmd/api`).

To check the whole module:

    go build ./...
    go vet ./...

## Run

    $env:BEARER_KEY = "<signing key>"
    .\guldvegt.exe

## Environment variables

- `BEARER_KEY` — **required**. HMAC signing key used to verify JWTs. The
  server refuses to start if it is unset or empty.
- `METRICS_URL` — **required**. Listen address and path of the Prometheus
  metrics server, e.g. `127.0.0.1:9081/metrics`. The server refuses to start
  if it is unset.
- `LOG_LEVEL` — optional. Log level: `error`, `info`, `debug`, `warning`.
  Defaults to `info`.

## Authentication

- Middleware `pkg/auth.BearerAuth` validates a JWT (HS256) from
  `Authorization: Bearer <token>`.
- Token claims: `name` (string), `role` (string), `exp` (expiration,
  required).
- Only unexpired tokens with `role: "reader"` are accepted.

## Logging

- Uses `log/slog` via `pkg/logger.SetupLogger()`.
- Echo v5 has native slog support: assign the logger to `server.Logger` and
  register `logger.RequestLogger()` with `server.Pre` for request logging
  (registered as pre-middleware so that requests rejected before routing,
  e.g. 404/405, are logged too).
- Requests answered with `200 OK` are logged at info level (`REQUEST`).
  Every response with any other status code is logged at error level
  (`REQUEST_ERROR`) together with the reason of the failure in the `reason`
  attribute.
- Successful authorization logs the user name at debug level; authorization
  failures return 401/403 with a generic message and the specific reason is
  recorded by the request logger at error level.
- Handlers write the error body themselves and return the underlying error,
  so the request logger records the actual failure reason.

## Health check

- `GET /health` returns `200 OK` with `{"status":"ok"}`. It is not part of the
  OpenAPI specification: the handler lives in `internal/api/health.go` and the
  path is registered explicitly in `cmd/api/main.go`.
- The path is passed to `auth.BearerAuth` as a public path and to
  `logger.RequestLogger` as a skipped path, so probes require no token and do
  not flood the request log.
- The binary supports a `healthcheck` subcommand that probes
  `http://127.0.0.1:9080/health` and exits with 0 (healthy) or 1. Both the
  image `HEALTHCHECK` and the compose health check run
  `/guldvegt healthcheck`, because the distroless runtime has no shell or
  HTTP client.

## Upstream providers

- Both quote endpoints aggregate data from several upstream providers that
  are queried concurrently.
- A failed provider is logged at error level (`provider request failed` with
  `endpoint`, `provider` and `error` attributes) and increments
  `guldvegt_provider_errors_total{endpoint, provider}`. It does not fail the
  whole request.
- The response is `200 OK` with the quotes returned by the providers that
  succeeded. `503 Service Unavailable` is returned only when no provider
  delivered any quote; such a request also increments
  `guldvegt_requests_failed_total{endpoint}`.
- Quote providers are registered with a lowercase identifier used in logs and
  metrics (`sberbank`, `vtb`, `zolotoy_zapas`, `zoloto_md`).

## Generated code

- `internal/generated/openapi/` is generated by
  [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) v2.8.0.
  Do **not** edit these files by hand.
- Regenerate from `api/openapi.yaml` with the local config files:

      oapi-codegen -config codegen-server.yaml api/openapi.yaml
      oapi-codegen -config codegen-types.yaml api/openapi.yaml

## General rules

- Go 1.26+ module (`github.com/TuliMyrskyTaivas/guldvegt`).
- Use Echo v5 conventions: handlers are `func(c *echo.Context) error`,
  middleware is `func(next echo.HandlerFunc) echo.HandlerFunc`.
- Keep changes minimal and focused; preserve existing naming and style.
- After changing dependencies, run `go mod tidy`.
- Do not commit secrets or `.env` files.
